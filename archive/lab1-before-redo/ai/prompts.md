# Реальні промпти та результати

Це журнал поточної переробки раніше перевіреної лабораторної.
Наведений запис не описує першу генерацію моделі. Попередні рішення
студента збережені дослівно в [audit.md](audit.md); цей файл не є
повним експортом попереднього діалогу. Попередні доступні промпти
ще потрібно додати з фактичних повідомлень, не реконструюючи їх.

## Етап документації — повідомлення студента дослівно

Текст загалом погоджую, але хочу трохи змінити підхід.

1. Залиши інформацію про мої реальні рішення: перегляд K1–K6, правила ключів, видач, бронювань і черги.
2. Збережи посилання на ai/audit.md та справжні SHA комітів.
3. Прибери тимчасовий перелік незавершених інструментів і перевірок із цього розділу. Поточний стан роботи можна відображати в README.md.
4. Не видаляй історію використання AI та не приписуй мені дій, яких я не виконував.
5. Не створюй окремий коміт лише заради цього тексту. Включи зміну до наступного змістовного коміту з документацією.

Після цього продовжуй наступний етап лабораторної, але перед комітом покажи мені всі зміни для перевірки.

## Результат AI цього етапу

Підготовлено нейтральний розділ погодження spec із посиланнями на
справжні коміти; поточний стан перенесено у README гілки розробки.
Створено три ADR про Mermaid, прямий Author–Book M:N та обчислення
доступності й права видачі. У кожному є Status, Context, Decision Drivers,
Considered Options, Decision та Consequences. ADR позначені як
запропоновані для перегляду, без твердження про підтвердження їхнього тексту.

ER-модель не змінена. Наявні дослівні записи audit.md збережені.
Студент ще не перевірив ці зміни; коміт і push на момент підготовки
цього запису не виконані. Запис фіксує результат підготовки файлів,
а не завершення всього аудиту або Definition of Done.

## Перевірка перед комітом

Студент попередньо погодив підготовлені зміни й дозволив один коміт
після перевірки. Це попереднє погодження документації, а не твердження
про виконання студентом технічних перевірок. Назви розділів альтернатив
у трьох ADR уточнено до `Alternatives (Considered Options)`.

## Завершення JavaScript-аудиту — промпт студента дослівно

Хочу зараз завершити етап JavaScript-аудиту й створити ОДИН змістовний коміт.

1. Перевір наявні незакомічені package.json і tools/.
2. Якщо tools/audit.js або тести ще не завершені — допрацюй їх відповідно до spec.md і критеріїв K1–K5.
3. Додай npm run audit і npm run test.
4. Перевір правильну ER-модель і навмисно некоректні тестові моделі.
5. Запусти npm run audit, npm test і git diff --check.
6. Не заявляй про автоматичну перевірку 3НФ, якщо вона не реалізована.
7. Переконайся, що не змінено ER-модель або погоджені доменні правила без необхідності.
8. Якщо всі перевірки успішні, створи ОДИН коміт:\
   feat(audit): add JavaScript ER model validation and tests
9. Після коміту покажи SHA, список файлів, результати тестів і git status.

Не створюй додаткових комітів.\
Не роби push, PR або merge.\
Не змінюй часові мітки Git.\
Якщо перевірки не проходять — спочатку виправ проблеми, а не коміть несправний код.

## Етап K6 — промпт студента дослівно

Продовжуй лабораторну роботу в гілці fix/lab1-ai-review.

Завдання — повністю завершити етап K6 (відтворюваність ER-діаграми).

1. Створи tools/render.js для генерації SVG і PNG з model/er.mmd через Mermaid CLI.
2. Додай необхідні залежності та package-lock.json для Node.js 22.
3. Налаштуй npm run render і npm run check.
4. Згенеруй SVG/PNG та додай їх до репозиторію.
5. Онови README.md з інструкціями встановлення, запуску та перегляду діаграми.
6. Перевір відповідність SVG/PNG вихідній ER-моделі та відсутність помилок генерації.
7. Запусти npm run audit, npm test, npm run render і npm run check.
8. Перевір, що генерація працює повторно та не створює зайвих змін.
9. Онови ai/prompts.md та ai/audit.md лише фактичними записами. Не вигадуй моїх особистих перевірок чи зауважень.
10. Не змінюй spec.md або model/er.mmd без необхідності.

Якщо всі перевірки успішні, ОДРАЗУ створи один змістовний коміт:

feat(render): add reproducible Mermaid rendering and checks

Після коміту покажи:

- SHA коміту;
- список змінених файлів;
- результати всіх перевірок;
- git status;
- що мені потрібно особисто переглянути для підтвердження ER-діаграми та 3НФ.

Не роби push, PR або merge. Не змінюй часові мітки Git.

Якщо виникнуть помилки, спочатку виправ їх і повтори перевірки. Не створюй коміт із непрацюючим кодом.
