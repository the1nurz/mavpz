# Lab 4 — Специфікація процесу видачі примірника

**Мета й вибір.** Описати оформлення видачі примірника читачеві: процес має поглиблений [UC-10](../lab2/uc-10-detail.md), US-06 та Sequence D33–D41, D48–D55. Основа: [ER](../model/er.mmd), [правила Lab 1](../spec.md), [EARS](../lab2/requirements.md) REQ-09, 11, 13, 15–19, 24; [історії](../lab2/user-stories.md), [Use Cases](../lab2/diagrams/use-cases.puml), [план Sequence](../lab3/spec.md). Це специфікація майбутньої поведінки, не реалізація.

**Межі, початок і завершення.** Початок — бібліотекар підтверджує видачу вибраного Copy наявному Reader з `loaned_at`, `due_at`. Завершення — підтвердження з `Loan.id`, обґрунтована відмова або невідомий клієнтові результат після втрати відповіді. Реєстрація, пошук, бронювання, повернення та фізична передача книги поза межами. UC-13/UC-17 — лише суміжний контекст сповіщення, не обов'язкові кроки UC-10.

**Учасники.** Бібліотекар ініціює; система перевіряє та фіксує; читач є одержувачем примірника. Зовнішній сервіс A1 бере участь лише в суміжному сповіщенні. Сховище — внутрішній учасник системи, не новий актор чи сутність ER.

**Кроки та розгалуження.**
1. Прийняти `reader_id`, `copy_id`, дати; перевірити сесію, право бібліотекаря, обов'язкові поля, Reader/Copy/Book і `due_at >= loaned_at` (рівність дозволена).
2. Обчислити UC-15: `Copy.state = active` та немає Loan з порожнім `returned_at`. Інакше відмовити через стан або відкриту видачу.
3. Визначити чергу лише active Reservation книги: `reserved_at`, потім лексикографічно канонічний UUID нижнього регістру. Черга порожня — дозволити; перший читач збігається — дозволити з виконанням першого бронювання; інший — відмовити через пріоритет.
4. Атомарно повторно перевірити актуальну доступність і право, створити Loan з новим UUID, поданими FK/датами, порожнім `returned_at`; за відповідної гілки перевести лише першу Reservation у `fulfilled`.
5. Після фіксації повідомити бібліотекарю `Loan.id`; причини відмов подавати українською без внутрішніх технічних даних.

**Винятки й паралельність.** X1/X2: відсутність сесії/права (401/403), полів/посилань — відмова без змін. X4: зайняті 50 HTTP-слотів — 503 за ≤1 с без змін. Збій до фіксації не залишає часткових змін; втрачена після фіксації відповідь не означає відкату (X3). Паралельні дії підтверджені [D40](../lab3/diagrams/uc-10-concurrent.mmd): два коректні запити одного доступного Copy без черги; рівно один успіх, іншому відмова через відкриту видачу. Це конкуренція двох запусків, не вигаданий fork усередині одного.

**Повідомлення та відповідь.** UC-10 передає результат бібліотекарю; реакція після успішного підтвердження не потрібна для завершення. У суміжних [D46](../lab3/diagrams/uc-13-transfer.mmd)/[D47](../lab3/diagrams/uc-17-transfer-failure.mmd) система передає A1 email першого читача, id і назву Book; помилку показує бібліотекарю. За [ADR-L2-0001](../lab2/adr/0001-notification-boundary.md) доставка й відповідь читача не гарантовані та не є передумовою видачі; нове звернення повторює перевірки. Автоматичне продовження після мовчання A1 не визначене.

**Питання.** Чи потрібне включення UC-13 в майбутню Activity як окремого суміжного потоку? Які очікування/тайм-аут для A1 та реакції читача? Як з'ясовувати результат втраченої відповіді UC-10 і обробляти повтор запиту? Джерела не встановлюють цих політик; нових строків, retry чи гарантії exactly-once не вводимо.

**Нотація.** PlantUML Activity обрано для явних дій, умов переходів, доріжок відповідальності та паралельних потоків. Текстове джерело зручне для Git і відтворення. ADR-0001 стосується Mermaid для ER; ER та Sequence залишаються незмінними. На етапі 1 діаграма не створюється.

**Критерії прийняття.** Один процес узгоджений з UC-10/US-06; описані успіх, відмови, конкуренція та межа повідомлень. Не більше одного відкритого Loan на Copy; Loan/fulfilled атомарні; інші бронювання, історія й Copy.state незмінні, доступність не зберігається ([ADR-0003](../adr/0003-derived-availability.md)). Невизначені політики залишені питаннями; Lab 1–3 незмінні; специфікація — до однієї сторінки.
