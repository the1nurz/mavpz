# Відтворення та перевірки етапу 4

Команди виконуються з кореня репозиторію у Windows x64.

```powershell
powershell -NoProfile -File lab4/tools/setup.ps1
node lab4/tools/validate.mjs --render
node lab4/tools/validate.mjs --check
git diff --check
```

`setup.ps1` завантажує портативний Temurin JRE 21.0.13+9 і PlantUML 1.2026.9 у `.cache/lab4`. URL та SHA-256 зафіксовані в `tools/toolchain.json`. Для іншого встановленого JRE можна задати `LAB4_JAVA` абсолютним шляхом до Java. Перевірений запуск використовував Node.js 24.22.1, Windows x64 і зафіксований Temurin. Парсер і рендер працюють локально з профілем PlantUML `SANDBOX`.

`--render` спочатку перевіряє структуру і справжній синтаксис командою PlantUML `-checkonly`, потім генерує SVG/PNG через `-pipe`. `--check` повторює генерацію в пам'яті та порівнює збережені файли побайтово. Маніфест містить SHA-256 нормалізованого джерела, валідатора, конфігурації інструментів та обох зображень, версію Java і платформу. Побайтове відтворення прив'язане до цього середовища, включно зі шрифтами. [Параметри PlantUML](https://plantuml.com/command-line)

Автоматичні перевірки охоплюють необхідні файли, обрамлення PlantUML, початковий і кінцеві вузли, парні if/else, fork/join, відповідального кожної дії, відправника й отримувача повідомлення, його зміст, реакцію та гілку тайм-ауту. Структурний обхід виявляє недосяжні дії, незавершені скінченні шляхи й дострокове завершення паралельної гілки перед join. Також перевіряються основні українські підписи SVG, заголовок і розміри PNG, контрольна сума JAR та актуальність рендеру. За відсутності Java/JAR виводиться `NOT RUN` для парсера, рендеру й актуальності з кодом 2. Помилки перевірок завершуються ненульовим кодом.

Виконаний `--check` пройшов перевірки для одного start, 11 stop, 12 пар if/else, одного fork/join із двома гілками та 28 дій. PlantUML `-checkonly` завершився кодом 0. SVG відкрито XML-парсером, PNG розміром 2726 × 2114 декодовано через System.Drawing. Візуально переглянуто весь PNG та збільшений фрагмент повідомлення. Українські символи, доріжки, умови, дві смуги fork/join та форми sendSignal/acceptEvent відображаються.

Додаткові негативні проби в локальному кеші відхилили вилучений join, помилкову роль відправника, недосяжну дію і змінений PNG. Окреме джерело з невідомою командою справжній PlantUML відхилив із кодом 200. PlantUML прийняв пробу з незакритим if, тому структурний контроль вкладеності доповнює перевірку парсером. Після проб повторний `--check` пройшов.

## Питання для етапу 5

| ID | Спостереження та потрібне уточнення |
|---|---|
| F4-01 | Spec підтверджує паралельність через конкурентні запуски D40. Поточний fork деталізує надсилання та очікування після commit у межах одного запуску. Потрібно узгодити цей рівень деталізації зі spec і D33/D54. |
| F4-02 | Обидві структурні гілки доходять до join, циклів немає. Однак acceptEvent може очікувати подію, а гілка «так» припускає її доступність. Потрібно перевірити модель доставки та кореляцію події. Структурна перевірка дає результат для скінченних шляхів, гарантія прогресу виконуваного процесу потребує окремого обґрунтування. |
| F4-03 | Тайм-аут має перехід до join, проте зараз представлений звичайною дією після умови доступності. Подія спливу очікування та її зв'язок з acceptEvent залишаються питанням. UC-10 X3/D54 описують спостереження тайм-ауту, його тривалість залишається відкритою. |
| F4-04 | Серверна гілка завершується після надсилання. Завершення всієї Activity через join також залежить від отримання й ознайомлення бібліотекаря або спостереження тайм-ауту. Слід зіставити цю залежність із твердженням spec про завершення видачі без подальшої відповіді бібліотекаря. |

Атомарна операція залишається однією дією перед fork. Її примітка охоплює актуальні перевірки, Loan і умовний fulfilled. Відмови до фіксації завершаються окремими кінцевими вузлами. Після втрати відповіді гілка зберігає вже оформлену видачу за D54. У графі одного запуску повторного входу до атомарної дії немає. Повторний HTTP-запит, з'ясування результату й захист від дублювання між запитами залишаються відкритими за UC-10 X3. Поведінкові перевірки застосунку мають статус `NOT RUN`.
