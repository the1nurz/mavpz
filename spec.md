# Специфікація ER-моделі «Бібліотека»

## Намір і межі

Лабораторна робота №1 описує каталог бібліотеки, читачів, примірники,
видачі та бронювання. Це переробка раніше перевіреної лабораторної,
а не перша спроба виконання завдання. Цей новий репозиторій фіксує
реальні етапи переробки; він не відтворює стару Git-історію.

Модель є концептуальною/логічною ER-моделлю. SQL, ORM, фізична схема БД
та реалізація операцій не входять до її меж. Джерело моделі —
`model/er.mmd`; JavaScript використовується для автоматизації перевірок
і рендеру, а не для зберігання самої ER-моделі.

## Сутності та атрибути

Book представляє конкретне видання з одним ISBN, роком публікації та
видавцем. Різні видання одного твору — окремі Book. Copy представляє
фізичний примірник цього видання. Це трактування підтверджене студентом.

Рівно сім сутностей. Назви у специфікації — PascalCase, у Mermaid —
UPPERCASE (`Publisher` → `PUBLISHER`). Назви атрибутів збігаються дослівно.
Типи — логічні типи Mermaid. PK — первинний ключ, FK — зовнішній ключ,
UK — унікальний альтернативний ключ; `—` означає відсутність позначення
ключа або посилання. Кожна сутність має рівно один `id PK`.

| Сутність | Атрибут | Тип | Ключ | Посилання |
|---|---|---|---|---|
| Publisher | id | uuid | PK | — |
| Publisher | name | string | — | — |
| Publisher | country | string | — | — |
| Author | id | uuid | PK | — |
| Author | full_name | string | — | — |
| Author | birth_year | int | — | — |
| Book | id | uuid | PK | — |
| Book | title | string | — | — |
| Book | isbn | string | UK | — |
| Book | publication_year | int | — | — |
| Book | publisher_id | uuid | FK | Publisher.id |
| Copy | id | uuid | PK | — |
| Copy | book_id | uuid | FK | Book.id |
| Copy | inventory_number | string | UK | — |
| Copy | state | string | — | — |
| Reader | id | uuid | PK | — |
| Reader | full_name | string | — | — |
| Reader | email | string | UK | — |
| Reader | registered_at | datetime | — | — |
| Loan | id | uuid | PK | — |
| Loan | reader_id | uuid | FK | Reader.id |
| Loan | copy_id | uuid | FK | Copy.id |
| Loan | loaned_at | datetime | — | — |
| Loan | due_at | datetime | — | — |
| Loan | returned_at | datetime | — | — |
| Reservation | id | uuid | PK | — |
| Reservation | reader_id | uuid | FK | Reader.id |
| Reservation | book_id | uuid | FK | Book.id |
| Reservation | reserved_at | datetime | — | — |
| Reservation | status | string | — | — |

Усі PK та FK мають тип `uuid`. Кожен FK посилається на наявний PK
відповідної сутності та має той самий тип. ISBN, інвентарний номер і email
є обов'язковими унікальними альтернативними ключами у межах своїх сутностей.

## Зв'язки та кардинальності

«Правих на одну ліву» визначає кількість екземплярів правої сутності
для одного екземпляра лівої; наступний стовпець читається навпаки.
`*` — необмежений максимум. Mermaid-вирази та підписи є частиною контракту.
Вертикальні риски у клітинках Markdown екрановані як `\|`.

| Ліва сутність | Права сутність | Правих на одну ліву | Лівих на одну праву | Mermaid | Підпис |
|---|---|---|---|---|---|
| Publisher | Book | 0..* | 1..1 | PUBLISHER \|\|--o{ BOOK | publishes |
| Author | Book | 0..* | 1..* | AUTHOR }\|--o{ BOOK | writes |
| Book | Copy | 0..* | 1..1 | BOOK \|\|--o{ COPY | has |
| Reader | Loan | 0..* | 1..1 | READER \|\|--o{ LOAN | borrows |
| Copy | Loan | 0..* | 1..1 | COPY \|\|--o{ LOAN | is lent in |
| Reader | Reservation | 0..* | 1..1 | READER \|\|--o{ RESERVATION | makes |
| Book | Reservation | 0..* | 1..1 | BOOK \|\|--o{ RESERVATION | is reserved in |

Рівно ці сім зв'язків присутні у моделі. Книга має щонайменше одного автора
та рівно одного видавця. Автор і видавець можуть поки не мати книг у каталозі.
Примірник належить рівно одній книзі; книга може поки не мати примірників.
Видача належить одному читачу та одному примірнику; бронювання — одному
читачу та одній книзі. Читач, примірник і книга можуть не мати відповідних
операцій. Історія примірника може містити багато видач у різний час.

Author–Book — прямий M:N без власних атрибутів і без проміжної сутності
`BookAuthor`. Loan та Reservation — асоціативні сутності з власними
атрибутами: датами видачі/бронювання і статусом бронювання. Окремі `id`
дозволяють повторні операції між тими самими учасниками.

## Правила предметної області

- `Copy.state` ∈ {`active`, `lost`, `written_off`} описує фізичний стан.
- Фізична доступність не зберігається: примірник фізично доступний тоді й лише тоді,
  коли `state = active` і немає його Loan із порожнім `returned_at`.
- Один примірник може мати щонайбільше одну відкриту видачу одночасно.
  Кардинальність історії `0..*` не виражає цього часового обмеження.
- `Loan.returned_at` може бути порожнім до повернення. `due_at >= loaned_at`;
  заповнений `returned_at >= loaned_at`. Дати інших атрибутів обов'язкові.
- `Reservation.status` ∈ {`active`, `fulfilled`, `cancelled`, `expired`}.
  Бронюється книга, а не конкретний примірник. Бронювання дозволене
  незалежно від наявності фізично доступних примірників. Повторні
  бронювання зберігаються як окремі Reservation з власними UUID.
- Активні бронювання однієї книги утворюють чергу за зростанням
  `reserved_at`; за однакового часу — за зростанням `id`.
  UUID порівнюються лексикографічно у канонічному записі нижнього регістру.
  Це лише детермінований порядок для однакових часових міток.
- Право конкретного читача отримати фізично доступний примірник
  визначається окремо: за наявності активних бронювань примірник спочатку
  пропонується читачу першого бронювання в черзі; читачу поза чергою
  видається лише за відсутності активних бронювань цієї книги.
  Виконане бронювання переходить у `fulfilled` і більше не бере участі
  в активній черзі. Право на видачу не зберігається окремим полем.

Переліки значень, обов'язковість полів і часові правила описані тут;
Mermaid не кодує їх повністю. Статичний аудит структури не доводить
виконання цих правил на реальних даних.

## Функціональні залежності та нормалізація

Для кожної сутності: `id → усі інші атрибути цієї сутності`.
Додаткові кандидатні ключі задають залежності:

- `Book.isbn → id, title, publication_year, publisher_id`;
- `Copy.inventory_number → id, book_id, state`;
- `Reader.email → id, full_name, registered_at`.

Імена авторів, читачів і видавців не вважаються унікальними. FK не є
кандидатними ключами. Пари `reader_id, copy_id` і `reader_id, book_id`
не визначають операцію через можливі повторення в історії.

Атрибути атомарні (1НФ); автори книги представлені зв'язком, а не списком
у полі Book. Усі кандидатні ключі одноатрибутні, тому часткових залежностей
від частини складеного ключа немає (2НФ). За прийнятих доменних припущень
немає функціональних залежностей між неключовими атрибутами. Для кожної
нетривіальної залежності визначник є суперключем, що задовольняє 3НФ.
Дані видавця не дублюються у Book, книги — у Copy, читача — у Loan/Reservation.
Похідна доступність не додається до Copy.

Це обґрунтування спирається на зазначені припущення й перевіряється людиною.
Прямий M:N є рішенням ER-рівня; відображення його у фізичну реляційну схему
потребуватиме окремого рішення у наступній роботі.

## Критерії прийняття

- **K1 — ключі.** Кожна сутність має рівно один `id PK`; усі PK/FK — `uuid`;
  кожен FK посилається на наявний PK відповідного типу.
- **K2 — кардинальності.** Рівно сім зв'язків із таблиці, з точними
  мінімальними та максимальними кардинальностями на обох сторонах.
- **K3 — нормалізація.** Функціональні залежності й відповідність 3НФ
  пояснені та перевірені вручну. Похідна доступність не зберігається.
- **K4 — M:N.** Author–Book — прямий M:N без проміжної сутності;
  Loan і Reservation — асоціативні сутності з власними атрибутами.
- **K5 — повна відповідність.** Spec і Mermaid мають однакові множини
  сутностей, атрибутів, типів, PK/FK/UK, зв'язків, кардинальностей і підписів;
  зайвих елементів та дублікатів немає. Єдина відмінність написання назв
  сутностей — визначене перетворення PascalCase → UPPERCASE.
- **K6 — відтворення.** Node.js 22 і `@mermaid-js/mermaid-cli` генерують
  SVG та PNG із `model/er.mmd`. `npm run audit`, `npm run render` і
  `npm run check` проходять. Тести приймають правильну модель та виявляють
  навмисні помилки у тестових копіях. Python не використовується.

## Погодження та поточний стан

Студент переглянув і погодив критерії K1–K6, сім сутностей та
кардинальності зв'язків. Під час перегляду розглянув правила ключів,
повторних видач і бронювань та надав власні рішення, зафіксовані
дослівно в [ai/audit.md](ai/audit.md).

За результатами цього перегляду змінено правило: бронювання книги
дозволене незалежно від наявності фізично доступних примірників.
Уточнено порядок черги за `reserved_at` та `id`, а також відмінність
між фізичною доступністю примірника і правом конкретного читача
отримати його з урахуванням активних бронювань.
