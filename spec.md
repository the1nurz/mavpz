# spec.md — ER-модель «Бібліотека»

**Намір.** Описати дані бібліотеки (каталог, читачі, видачі, бронювання) як
модель сутностей і зв'язків, придатну для подальших завдань курсу
(вимоги → взаємодія → процес → архітектура).

## Сутності та атрибути

| Сутність | Атрибути (PK — первинний, FK — зовнішній, UK — унікальний) |
|---|---|
| Publisher | id (PK), name, country |
| Author | id (PK), full_name, birth_year |
| Book | id (PK), title, isbn (UK), publication_year, publisher_id (FK) |
| Copy | id (PK), book_id (FK), inventory_number (UK), status |
| Reader | id (PK), full_name, email (UK), registered_at |
| Loan | id (PK), reader_id (FK), copy_id (FK), loaned_at, due_at, returned_at |
| Reservation | id (PK), reader_id (FK), book_id (FK), reserved_at, status |

## Зв'язки (словами)

1. Видавець випускає багато книг; книга має рівно одного видавця.
2. Автор пише багато книг, книга має одного або кількох авторів
   (**багато-до-багатьох**, без власних атрибутів → окремої сутності немає).
3. Книга має багато примірників; примірник належить одній книзі.
4. Читач бере багато видач; кожна видача належить одному читачу.
5. Примірник може фігурувати у багатьох видачах (в різний час).
6. Читач робить багато бронювань; кожне бронювання одного читача.
7. Книга може бути заброньована багато разів.

Видача й бронювання — **асоціативні сутності**: зв'язок читача з
примірником/книгою несе власні атрибути (дати, статус).

## Критерії прийняття

- **K1 (ключі).** Кожна сутність має первинний ключ `id`; усі `id` і
  зовнішні ключі мають однаковий тип `uuid`. Перевіряється автоматично:
  `python3 tools/audit.py` має завершитись з кодом 0 (разом з K5).
- **K2 (кардинальності).** Кожен зв'язок з розділу «Зв'язки» присутній у
  діаграмі з відповідною кардинальністю.
- **K3 (нормалізація).** Модель у 3НФ: немає часткових і транзитивних
  залежностей; немає похідних даних, що дублюються.
- **K4 (M:N).** «Багато-до-багатьох» показано прямим зв'язком; спільних
  таблиць на кшталт `author_books` немає. Асоціативна сутність — лише коли
  є власні атрибути.
- **K5 (імена).** Назви полів у діаграмі збігаються з назвами в spec.
- **K6 (рендер).** `model/er.svg` згенеровано з `model/er.mmd` і збігається
  з описом.
