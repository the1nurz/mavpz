# ADR-0001 — Mermaid як джерело ER-моделі

## Status

Прийнято. Студент підтвердив прийняття ADR-0001 у фінальному перегляді;
дослівне повідомлення наведене в [ai/audit.md](../ai/audit.md).

## Context

Специфікація визначає сім сутностей, їхні атрибути, ключі та сім зв'язків.
Модель повинна залишатися в `model/er.mmd`, а SVG/PNG відтворюватися
автоматично без Python. Наявний файл моделі створено в
[4d4cf8a](https://github.com/the1nurz/mavpz/commit/4d4cf8ad1511fb7e6ed9dbc0bdd3a43a5228f9fe).

## Decision Drivers

- Пряма вимога студента зберігати ER-модель у Mermaid.
- Потреба явно показати PK/FK/UK і мінімальні та максимальні кардинальності.
- Перевірювані текстові зміни в Git і спільне джерело SVG та PNG.
- Вимога автоматизації на JavaScript, Node.js 22, через Mermaid CLI.

## Alternatives (Considered Options)

1. Mermaid `erDiagram` і `@mermaid-js/mermaid-cli`.
2. PlantUML — потребує іншого формату й іншого ланцюжка рендеру.
3. Ручний рисунок — ускладнює перевірку відповідності та відтворення.

## Decision

Використовувати `model/er.mmd` як джерело структури моделі, а spec.md —
як контракт для її перевірки. Реалізований `tools/render.js` викликає
Mermaid CLI для генерації SVG/PNG. Окрему JavaScript-копію ER-моделі
не створювати. Рендер і побайтову перевірку реалізовано в
[8bd3790](https://github.com/the1nurz/mavpz/commit/8bd37905d310216e64e5fa2ef25281bb9c54137d).

## Consequences

Текстову модель можна звіряти зі spec й переглядати в Git. CLI потребує
Node.js та браузерного середовища для рендеру. Mermaid не виражає повністю
часові обмеження, обов'язковість полів і правила черги, тому вони
залишаються у spec та потребують ручної перевірки.
