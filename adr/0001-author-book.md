# ADR-0001 — Прямий M:N між Author і Book

## Status

Задокументовано чинне рішення моделі. Текст ADR підготовлено AI-помічником для перегляду.

## Context

[K1](../spec.md) вимагає щонайменше одного автора кожної книги та допускає співавторство й кілька книг автора. Чинна ER-модель містить сім сутностей і прямий `Author }|--o{ Book`. Атрибутів зв'язку, наприклад порядку чи ролі автора, специфікація не задає.

## Decision Drivers

- Підтримка кількох авторів книги та кількох книг автора.
- Мінімум один автор на книгу; модель допускає автора без книг.
- Відсутність заданих власних атрибутів зв'язку.
- Збереження семи сутностей і меж ER-моделювання без SQL DDL та ORM.

## Decision

Зберегти прямий M:N `Author }|--o{ Book : writes` без проміжної сутності. Не додавати author_id до Book: один такий FK не описує співавторство.

## Alternatives

- BookAuthor із двома FK: доцільний для фізичної реляційної схеми або появи атрибутів зв'язку; для поточного ER-рівня додаткова сутність не потрібна.
- Один author_id у Book: не підтримує кількох авторів.
- Список авторів у текстовому полі Book: ускладнює ідентифікацію авторів і моделювання зв'язків.

## Consequences

Діаграма прямо показує вимогу K1 без восьмої сутності. У фізичній реляційній реалізації знадобиться окреме рішення щодо таблиці зв'язку. Якщо з'являться ролі або порядок співавторів, вимоги й ADR потрібно переглянути. K2–K6 це рішення не змінює.
