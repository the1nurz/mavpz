# 0001. Mermaid erDiagram як декларативне джерело моделі

* Статус: прийнято
* Дата: 2026-10-06

## Контекст і проблема

Завдання вимагає ER-модель у декларативному синтаксисі (Mermaid `erDiagram`
або PlantUML) і рендер, що збігається з описом. Потрібен формат, який
рев'юер бачить прямо в GitHub PR без додаткових інструментів.

## Варіанти

* Mermaid `erDiagram`
* PlantUML
* Малювати діаграму вручну в редакторі (відкинуто: не декларативно)

## Рішення

Обрано **Mermaid `erDiagram`** (`model/er.mmd`).

* GitHub рендерить блок ` ```mermaid ` нативно — рев'юер бачить діаграму в
  PR без Java/сервера (на відміну від PlantUML).
* Синтаксис має PK/FK/UK і всі чотири кардинальності, потрібні моделі.
* Статичний `er.svg`/`er.png` генерує `tools/render.py` **із самого
  `er.mmd`** (Graphviz, нотація «воронячої лапки»). `mermaid-cli` у
  робочому середовищі встановити не вдалося (реєстр npm відхилив пакет),
  тому рендер статичних файлів зроблено власним скриптом; еталонний
  Mermaid-рендер — `model/er.md` на GitHub.

## Наслідки

* Плюс: одне джерело істини, рендер відтворюваний однією командою.
* Мінус: вигляд `er.svg` (Graphviz) відрізняється від Mermaid-рендера на
  GitHub; зміст (сутності, поля, кардинальності) той самий і береться з
  одного файлу.
