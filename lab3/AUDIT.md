## Три найважливіші нові технічні розбіжності

### A-01 — два видавці не були явно передані валідатору

Файл: [D21](diagrams/uc-05-two-publishers.mmd), UC-05, SC-12 Examples №4, REQ-11, ER Publisher–Book (рівно один видавець).

Доказ у початковому cf127d9: виклик UI → S містив `addBook(..., publisher_id, authorIds)`, а наступний self-call — `validateBookCardinalities(publisherIds, authorIds)`. Вхідний параметр одиничний, колекція publisherIds не отримана жодним попереднім повідомленням; напис «два видавці» не пояснював рух обох значень.

Вплив: негативний приклад Gherkin мав неоднозначний вхід; за послідовністю параметрів не видно, що перевіряються саме два видавці. Це дефект опису даних, не доведений runtime-баг застосунку.

Варіанти: явно передати два сирі значення форми або окремо показати її читання перед валідацією. Обрано перший мінімальний варіант: `publisherIds=[P1, P2]` і нотатка, що це некоректний вхід, не новий атрибут Book. У домені залишається один Book.publisher_id, запису немає. Бізнес-вибір студента не потрібен.

Виправлено комітом [30103e22bff10ecb0d98733bf91b5f35c8490cba](https://github.com/the1nurz/mavpz/commit/30103e22bff10ecb0d98733bf91b5f35c8490cba).

### A-02 — X2 не передавав конкретні поля помилок до UI

Файли: [D51](diagrams/uc-10-x2-fields.mmd), [D52](diagrams/uc-10-x2-references.mmd), UC-10/X2, REQ-11, NFR-11. Прямих SC для X2 немає, це не нове Gherkin-покриття.

Доказ у cf127d9: D51 повертав із self-call «Перелік незаповнених полів», але S → UI та UI → актор лише «Заповніть позначені обов’язкові поля», без самого переліку. D52 повертав «Відсутній Reader, Copy або пов’язаний Book», далі лише вказівку «вказати відсутнє посилання». REQ-11 вимагає вказати порушений атрибут/зв’язок; NFR-11 — причину і поле помилки введення.

Вплив: не було явного наскрізного результату, з якого UI може позначити саме відповідне поле. Проста інструкція «вказати» залишала цю вимогу недоописаною.

Варіанти: передати структуровані помилки або конкретизувати всі можливі текстові результати. Обрано структуровані логічні результати `fieldErrors` та `referenceError(field, reason)` через усі returns. У D52 наведені відповідні Loan.reader_id, Loan.copy_id і Copy.book_id; пріоритет кількох помилок не встановлено. Нових прав, записів або HTTP-кодів немає. Рішення студента не потрібне: це деталізація чинного REQ/NFR.

Виправлено комітом [90e41752cf0f1e0102da185270a4ab3a0732587d](https://github.com/the1nurz/mavpz/commit/90e41752cf0f1e0102da185270a4ab3a0732587d).

### A-03 — повідомлення бібліотекарю помилково позначене return

Файл: [D47](diagrams/uc-17-transfer-failure.mmd), UC-17 як розширення UC-13; також UC-10/X5, SC-26, REQ-23/24.

Доказ у cf127d9: після `Flow->>UI: showNotificationFailure(...)` спочатку йшов `UI-->>Flow`, завершувалась активація Flow, а потім `UI-->>L`. Попереднього виклику `L->>UI` у діаграмі немає. Тому пунктирне повідомлення бібліотекарю не було відповіддю на його запит.

Вплив: тип і порядок повідомлень створювали хибну модель ініціатора взаємодії. Баланс bars і Mermaid.parse це не виявляли.

Варіанти: односторонній показ помилки або явна користувацька операція читання сповіщення. Другий варіант потребував би неописаної операції; його не додано. Використано `UI-)L` перед справжнім return `UI-->>Flow`; активації завершені після обробки. Це позначення виходу UI, без вибору push/polling, протоколу A1, гарантії доставки чи нової користувацької операції.

Оновлено перевірку текстів SVG для `-)` і тест. Новий регресійний контроль усіх 59 джерел шукає зворотний виклик для кожного dashed return; це евристика наявності пари, не доказ часової коректності всіх UML-трас. Рішення студента не потрібне.

Виправлено комітом [78eb5fe54b153b59cd89e53593cfa7d32cd68ffd](https://github.com/the1nurz/mavpz/commit/78eb5fe54b153b59cd89e53593cfa7d32cd68ffd).

Переглянуто цілі зображення зі зменшенням; українські символи, змінені повідомлення й activation bars видимі, критичних обрізань/накладань у цій вибірці не виявлено. Це не огляд усіх 59 PNG і не читання кожного пікселя. Довгі підписи потребують масштабу SVG. Автоматичні перевірки всіх 118 артефактів не називаються повною візуальною перевіркою.
