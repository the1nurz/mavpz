## Залежності та встановлення

Усі команди нижче виконуються з кореня репозиторію. Потрібні Node.js `>=22.13 <23`, npm, мережа лише для первісного встановлення та дозвіл запуску локального headless-браузера.

```sh
npm ci --no-audit --no-fund
```

Використовується вже наявний кореневий lock-файл: Mermaid CLI **12.0.0**, Mermaid **12.2.0**, Puppeteer **25.13.0**, його Chrome **155.0.8059.39**. Скрипт перевіряє точні версії пакетів і використовує модуль `renderMermaid` самого Mermaid CLI, повторно використовуючи один браузер. Не застосовуються `npx latest`, системний Chrome чи залежності сусіднього 2lab.

Puppeteer завантажує свій браузер у `.cache/puppeteer` за наявним .puppeteerrc.cjs. Не встановлюйте `PUPPETEER_SKIP_DOWNLOAD`, якщо сумісного браузера немає. Після завершеного npm ci повторне встановлення для кожного рендеру не потрібне.

## Команди

```sh
# Трасування, всі 51 випадки обліку й activation bars по гілках
node lab3/tools/check-sequences.mjs

# Синтаксис усіх 59 джерел без запису зображень
node lab3/tools/render-sequences.mjs --syntax-only

# Генерація або повторна генерація всіх SVG та PNG
node lab3/tools/render-sequences.mjs

# Перевірка актуальності без перезапису збережених зображень
node lab3/tools/render-sequences.mjs --check

# Тести перевіряльника, включно з пошкодженими PNG й дисбалансом гілок
node --test lab3/test/render-sequences.test.mjs

# Усі тести, включно з трьома регресіями незалежного аудиту
npm test

# Перевірки попередніх робіт
node tools/audit.js
node lab2/tools/check-traceability.mjs
node lab2/tools/check-uc10.mjs
git diff --check
```

Скрипти знаходять корінь від власного розташування, тому абсолютний запуск з іншого cwd також працює. Відсутня залежність, джерело, пошкодження, помилка синтаксису чи рендеру дає ненульовий код; помилки окремих діаграм містять ім'я .mmd. Неочікувані зайві SVG/PNG не видаляються автоматично.

## Структура та відтворюваність

```text
lab3/
  README.md
  spec.md
  traceability.md
  AUDIT.md
  diagrams/
    README.md
    *.mmd                    # 59 джерел
    svg/*.svg                # 59 рендерів
    png/*.png                # 59 рендерів, scale 2
    render-manifest.json
  tools/
    render-sequences.mjs
    render-validation.mjs
    check-sequences.mjs
    mermaid-config.json
  test/
    render-sequences.test.mjs
    sequence-audit.test.mjs
```

[Конфігурація](tools/mermaid-config.json) задає білий фон, темний текст і стрілки, блакитні activation bars, Arial 15–16 px, перенесення довгих повідомлень і повторення учасників унизу. Viewport 1600×1000 та scale 2 зафіксовані в renderer. PNG зберігає повну висоту й ширину діаграми, а не лише перший екран. Довгі UC-10 краще читати у SVG з масштабуванням або PNG у натуральному розмірі. Перенесення можуть додавати дефіс усередині довгої назви операції.

Маніфест містить SHA-256 джерел, конфігурації, скриптів і lock-файлу, версії середовища, розміри, результати текстових/геометричних перевірок і хеші SVG/PNG. Часові мітки не використовуються як доказ актуальності. `--check` знаходить відсутні/зайві артефакти, змінені джерела й конфігурацію, пошкоджені PNG/SVG, потім порівнює всі зображення зі свіжим рендером побайтово. Записувальний режим перевіряє весь комплект до оновлення вихідних файлів; тимчасові результати прибираються після запуску.

Локальний lab3/.gitattributes фіксує LF для джерел, скриптів, JSON і SVG та binary для PNG, щоб Git не змінював байти цих файлів під час checkout.

Відтворюваність перевірена в тому самому середовищі: Node.js 22.23.3, Windows x64, Arial, зафіксований Chrome. Встановлені в ОС шрифти не вбудовуються в SVG. Інша ОС, шрифти, версія Node або браузера можуть змінити геометрію/байти; `--check` не приховує таку різницю. Для перенесення на інше середовище потрібна свідома регенерація та перегляд.

## Перевірки та їхні межі

Автоматично перевіряються XML/namespace/viewBox SVG; наявність усіх підписів учасників, повідомлень, нотаток, заголовків і guard-умов з урахуванням переносів; український текст; декодування PNG в браузері, IHDR, CRC кожного chunk, IDAT і scanlines; ненульові розміри. Геометрична евристика перевіряє вихід текстів, ліній, стрілок і фігур за межі SVG та значні перетини текстових прямокутників. Вона не є повним візуальним оглядом і не доводить семантику UML.

Перша спроба перевірки рендерів завершилася помилками: порівняння тексту не враховувало дефіси переносу, а mirrorActors=false залишав lifeline невідповідної довжини. Результати тоді не записувалися. Перевірку переносів уточнено; після вибіркового перегляду ввімкнено mirrorActors=true, усі джерела залишені незмінними. Залежності після переривання не перевстановлювалися: npm ci завершилося exit 0, використано його результати.

Фактичний перелік остаточно переглянутих зображень та підсумки перевірки наведено в [індексі](diagrams/README.md). Це вибірковий перегляд, не підтвердження студента і не огляд усіх 59 зображень.

Підсумок автоматичних запусків: синтаксис 59/59 PASS, рендер 59 SVG + 59 PNG PASS, остаточне побайтове --check PASS, перевірка трасування й активацій PASS, ER-аудит та перевірки Завдання 2 PASS, git diff --check PASS. Повний node --test: 51/51 PASS (44 попередні + 7 нових). Окремі негативні інтеграційні перевірки дали очікуваний ненульовий код для відсутнього SVG, зайвого PNG, зміненого джерела, пошкоджених PNG/SVG і зміненої конфігурації; оригінали після них відновлено байт у байт.

Перший staged git diff --check виявив зайві порожні рядки наприкінці чотирьох нових JS-файлів. Виправлено лише EOF-форматування, оновлено хеші цих скриптів у маніфесті; після цього повторено свіжий побайтовий контроль рендерів і staged-перевірку.
