# Завдання 1 — Домен і модель даних (ER): Бібліотека

## Домен

Міська бібліотека з абонементом. Читач реєструється, переглядає книги
в каталозі, може **забронювати** видання, коли всі примірники на руках, і
**взяти примірник додому** на певний строк.

Чому саме цей домен: у ньому природно виникають обидва випадки зі
вимог завдання — зв'язок «багато-до-багатьох» без власних атрибутів
(автор ↔ книга) і зв'язок, що несе власні атрибути (читач ↔ примірник —
видача; читач ↔ книга — бронювання).

## Структура репозиторію

| Файл | Призначення |
|---|---|
| `spec.md` | сутності, атрибути, зв'язки словами + критерії прийняття |
| `model/er.mmd` | ER-модель у Mermaid `erDiagram` (джерело істини для рендеру) |
| `model/er.svg` | рендер діаграми |
| `tools/` | `audit.py` (перевірка spec ↔ модель), `render.py` (рендер із `er.mmd`) |
| `adr/` | рішення за MADR |
| `DEFENSE.md` | точка входу для рев'ю |

## Передумови

Для генерації `model/er.svg` і `model/er.png` потрібен Graphviz (`dot`) у `PATH`.
Після встановлення виконайте:

```bash
python tools/render.py
```

## Межі

Тут лише концептуальна/логічна ER-модель. Фізичної схеми БД (SQL DDL, ORM)
немає — це предмет курсу баз даних.
