# Лабораторна №1 — «Бібліотека»: нова спроба

Модель описує бібліотечний каталог, фізичні примірники, читачів, видачі та бронювання. Вимоги й критерії K1–K6 наведені в [spec.md](spec.md). Робота містить ER-модель Mermaid; SQL DDL, ORM та реалізація операцій БД до її складу не входять.

## Сутності

| Сутність | Призначення |
|---|---|
| Publisher | Видавець; кожна книга має одного видавця |
| Author | Автор; книга має щонайменше одного автора, допускається співавторство |
| Book | Бібліографічні відомості книги, зв'язки з авторами та видавцем |
| Copy | Фізичний примірник однієї книги; кожна книга має щонайменше один примірник |
| Reader | Читач, якому видають примірники та який бронює книги |
| Loan | Історичний запис видачі примірника читачу; returned_at = NULL означає активну видачу |
| Reservation | Бронювання книги читачем; черга впорядкована за created_at, потім id |

У діаграмі 7 сутностей, 27 атрибутів і 7 зв'язків. У кожної сутності один `int id PK`; шість FK мають тип `int`, як і цільові PK. ISBN та інвентарний номер позначено UK. Author–Book — прямий M:N на ER-рівні.

## Перевірка та рендер

Команди нижче виконуються **з кореня репозиторію**, який містить `package.json`. Потрібні Node.js 22.13–22.x, npm і браузер Puppeteer. Залежності встановлюються за кореневим lock-файлом; Mermaid CLI 12.0.0 зазначено в package.json. Puppeteer використовує `.cache/puppeteer` через кореневий `.puppeteerrc.cjs`; під час першого встановлення потрібна мережа.

```sh
npm ci
npm run audit
npm test
npm run render
npm run check
git diff --check
```

`npm run audit` читає кореневі spec.md та model/er.mmd і перевіряє сім сутностей із точними назвами, 27 атрибутів, типи, 7 PK, 6 FK, 2 UK та сім зв'язків із кардинальностями. Перелік атрибутів є контрольованою структурною базою прийнятої AI-моделі, а не додатковими вимогами, приписаними студенту. FK перевіряються за визначеними цілями PK та відповідними зв'язками.

Специфікація читається як перелік сутностей і K1–K6, без старих таблиць. Аудитор зіставляє погоджені формулювання критеріїв та коментарів Mermaid після нормалізації пробілів, регістру й апострофів. Це контрольований формат, а не універсальний аналіз природної мови: змінене формулювання потребує ручного перегляду контракту та тестів. Відсутні або змінені правила K3–K5 і додаткові нерозпізнані коментарі про видачі/бронювання спричиняють помилку. Довільні перефразування чи суперечності поза підтримуваними фрагментами не аналізуються семантично.

`npm test` запускає тільки test/audit.test.js для Lab 1: позитивні перевірки та негативні сценарії неправильних ключів, сутностей, типів, кардинальностей і K1–K6 на копіях тексту. Тести не змінюють модель і не є доказами історичних помилок AI.

`npm run render` спочатку виконує аудит, потім Mermaid CLI розбирає синтаксис і генерує SVG/PNG із кореневого model/er.mmd. `tools/mermaid-config.json` задає оформлення, шрифт і детерміновані ID. Артефакти оновлюються лише за зміни байтів. `npm run check` виконує аудит, тести й повторний рендер у тимчасовому каталозі та побайтово порівнює SVG/PNG без їх перезапису. Відсутній або застарілий рендер дає ненульовий код. Побайтова тотожність між різними ОС не гарантується.

Відкрийте SVG або PNG та перевірте читабельність усіх 7 сутностей, 27 атрибутів, PK/FK/UK і 7 зв'язків. Для оцінки K1–K6 зіставте діаграму з таблицею нижче. Коментарі джерела не виводяться на зображення, тому правила активних видач і черги слід читати також у spec та er.mmd.

K4 і K5 перевіряються як узгоджені текстові правила специфікації та коментарів. Аудитор не створює записів Loan/Reservation і не доводить виконання обмежень на реальних даних. Загальна нормалізація та предметна коректність поза контрольованими перевірками потребують ручної оцінки.

Історичні матеріали залишаються доступними: [знімок нової спроби](lab1-redo/README.md), [її первинна AI-відповідь](lab1-redo/ai/first-response.md), [архів попередньої роботи](archive/lab1-before-redo/README.md). Чинними для перевірок є кореневі файли; історичні копії й їхні старі інструкції не оновлюються.

## Відповідність критеріям

| Критерій | Як представлено й перевіряється |
|---|---|
| K1 — автори | `Author }\|--o{ Book`: 1..* авторів на книгу; [ADR-0001](adr/0001-author-book.md) |
| K2 — примірники | `Book \|\|--\|{ Copy`: 1..* примірників на книгу |
| K3 — бронювання | FK Reservation.book_id → Book.id, зв'язку Reservation–Copy немає; незалежність від доступності описана в [ADR-0002](adr/0002-book-reservation.md) |
| K4 — видачі | Copy–Loan: 0..* історичних видач; максимум один Loan із returned_at = NULL на Copy, [ADR-0003](adr/0003-loan-history.md) |
| K5 — черга | Коментарі er.mmd та spec: created_at за зростанням, потім Reservation.id за зростанням |
| K6 — видавець | `Publisher \|\|--o{ Book`, Book.publisher_id → Publisher.id: один видавець на книгу |

K3–K5 містять правила операцій, які самі кардинальності й рендер не забезпечують на даних. У новій спробі зафіксовано 0 підтверджених початкових помилок AI: A1–A3 — уточнення та зміна вимог, а не три початкові помилки. Генерація відбувалася в сесії з попереднім контекстом; повної ізоляції не заявлено.
