# Лабораторна №1 — «Бібліотека»: нова спроба

Модель описує бібліотечний каталог, фізичні примірники, читачів, видачі та бронювання. Вимоги й критерії K1–K6 наведені в [spec.md](spec.md). Робота містить ER-модель Mermaid; SQL DDL, ORM та реалізація операцій БД до її складу не входять.

## Сутності

| Сутність | Призначення |
|---|---|
| Publisher | Видавець; кожна книга має одного видавця |
| Author | Автор; книга має щонайменше одного автора, допускається співавторство |
| Book | Бібліографічні відомості книги, зв'язки з авторами та видавцем |
| Copy | Фізичний примірник однієї книги; кожна книга має щонайменше один примірник |
| Reader | Читач, якому видають примірники та який бронює книги |
| Loan | Історичний запис видачі примірника читачу; returned_at = NULL означає активну видачу |
| Reservation | Бронювання книги читачем; черга впорядкована за created_at, потім id |

У діаграмі 7 сутностей, 27 атрибутів і 7 зв'язків. У кожної сутності один `int id PK`; шість FK мають тип `int`, як і цільові PK. ISBN та інвентарний номер позначено UK. Author–Book — прямий M:N на ER-рівні.

## Перевірка та рендер

Команди нижче виконуються **з кореня репозиторію**, який містить `package.json`, а не з папки lab1-redo. Потрібні Node.js 22.13–22.x, npm і браузер Puppeteer. Залежності встановлюються за кореневим lock-файлом; Mermaid CLI 12.0.0 зазначено в package.json. Puppeteer використовує `.cache/puppeteer` через кореневий `.puppeteerrc.cjs`; під час першого встановлення потрібна мережа.

```sh
npm ci
npx --no-install mmdc -i lab1-redo/model/er.mmd -o lab1-redo/model/er.svg -c tools/mermaid-config.json -b white --size 3000 -s 2
npx --no-install mmdc -i lab1-redo/model/er.mmd -o lab1-redo/model/er.png -c tools/mermaid-config.json -b white --size 3000 -s 2
git diff --check
```

Обидва виклики CLI розбирають Mermaid-синтаксис і рендерять саме нову модель. Спільний `tools/mermaid-config.json` задає оформлення, шрифт і детерміновані ID; він не є джерелом структури моделі. За незмінних залежностей, браузера та шрифтів повторіть команди й порівняйте зображення. Побайтова тотожність між різними ОС не гарантується.

Відкрийте SVG або PNG та перевірте читабельність усіх 7 сутностей, 27 атрибутів, PK/FK/UK і 7 зв'язків. Для оцінки K1–K6 зіставте діаграму з таблицею нижче. Коментарі джерела не виводяться на зображення, тому правила активних видач і черги слід читати також у spec та er.mmd.

Кореневі `npm run audit`, `npm run render` і `npm run check` налаштовані на попередню спробу в кореневих spec.md та model/er.mmd. Їхній успіх не є перевіркою lab1-redo. Окремого автоматизованого семантичного аудитора нової спроби ще немає; наведені команди перевіряють синтаксис і рендер, а відповідність предметним правилам оцінюється окремо.

## Відповідність критеріям

| Критерій | Як представлено й перевіряється |
|---|---|
| K1 — автори | `Author }\|--o{ Book`: 1..* авторів на книгу; [ADR-0001](adr/0001-author-book.md) |
| K2 — примірники | `Book \|\|--\|{ Copy`: 1..* примірників на книгу |
| K3 — бронювання | FK Reservation.book_id → Book.id, зв'язку Reservation–Copy немає; незалежність від доступності описана в [ADR-0002](adr/0002-book-reservation.md) |
| K4 — видачі | Copy–Loan: 0..* історичних видач; максимум один Loan із returned_at = NULL на Copy, [ADR-0003](adr/0003-loan-history.md) |
| K5 — черга | Коментарі er.mmd та spec: created_at за зростанням, потім Reservation.id за зростанням |
| K6 — видавець | `Publisher \|\|--o{ Book`, Book.publisher_id → Publisher.id: один видавець на книгу |

K3–K5 містять правила операцій, які самі кардинальності й рендер не забезпечують на даних. У новій спробі зафіксовано 0 підтверджених початкових помилок AI: A1–A3 — уточнення та зміна вимог, а не три початкові помилки. Генерація відбувалася в сесії з попереднім контекстом; повної ізоляції не заявлено.
