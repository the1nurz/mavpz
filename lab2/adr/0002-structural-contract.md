# ADR-L2-0002 — Структурний контракт і поведінкові Use Cases

Статус: фіксує спосіб подання вже прийнятих вимог у документації №2.

## Context

REQ-10 вимагає збереження структури ER, UUID PK/FK, прямого M:N і відсутності
збереженої похідної доступності. Це властивості моделі, а не ціль окремого
звернення користувача. US-09 задає мотив цілісності, SC-11 — перевірку контракту.
Матриця повинна чесно пояснити відсутність самостійного Use Case для REQ-10.

## Decision Drivers

- Предметний зміст UML: Use Case описує поведінку заради цілі актора.
- Відсутність штучної операції «перевірити ER» у застосунку.
- Прозорість трасування та відмінність структури від поведінки.
- Збереження договору №1 без повторного рішення про M:N або доступність.

## Alternatives

1. Структурний REQ-10 → US-09 → SC-11 → наскрізний контракт легенди;
   у матриці окремий статус «Структурно» та відсутність окремого UC.
2. Додати UC «Перевірити структуру ER» для бібліотекаря — приписує йому
   неописану дію майбутнього застосунку.
3. Приєднати REQ-10 до всіх UC без пояснення — створює формальні зв'язки
   й змішує структуру з реалізованою поведінкою.

## Decision

Використовувати варіант 1. Для REQ-10 допустима відсутність UC лише за
наявності US-09, SC-11, легенди й пояснення в матриці. Структурний аудит
звіряє ER зі spec №1. Поведінковий REQ-09 і SC-09/SC-10/SC-14/SC-24
окремо задають обчислення доступності. REQ-11/REQ-12 є наскрізними
обмеженнями з прикладами в конкретних операціях та легендою.

## Consequences

Усі 15 поточних UC мають вимоги; не кожна вимога мусить породжувати новий UC.
Повне охоплення ID не дорівнює виконанню сценаріїв або перебору всіх даних.
Трасувальний скрипт дозволяє структурний виняток тільки для REQ-10.
Семантика правил, хронологія й конкуренція потребують окремих перевірок.
Нових предметних рішень про чергу чи схему не приймається; вони успадковані
з [ADR №1-0002](../../adr/0002-author-book-many-to-many.md) та
[ADR №1-0003](../../adr/0003-derived-availability.md).

## Докази та межі перевірки рішення

Контракт представлений у SC-11, легенді PlantUML та рядку REQ-10 матриці;
скрипт check-traceability допускає відсутність UC лише для цього рядка.
Визначення доступності на даних лишається поведінковою вимогою REQ-09.
Наявність перелічених артефактів перевіряється, виконання застосунку — ні.
NFR не додаються до цього структурного ланцюжка для штучного збільшення
покриття. Ітеративний порядок створення зафіксовано в [аудиті](../audit.md).
